# 🚀 Production Deployment Guide

This guide outlines the steps to deploy the **Claw Machine Membership System** to production.

## 1. Installation & Requirements

### Prerequisites
*   **Node.js**: v18.17.0 or later (v20 recommended).
*   **Package Manager**: npm or yarn.
*   **Git**: For version control.

### Local Setup
1.  Clone the repository:
    ```bash
    git clone <your-repo-url>
    cd wawag
    ```
2.  Install dependencies:
    ```bash
    npm install
    ```
3.  Run locally:
    ```bash
    npm run dev
    ```

---

## 2. Firebase Setup

1.  **Create Project**: Go to [Firebase Console](https://console.firebase.google.com/) and create a new project.
2.  **Authentication**:
    *   Go to **Build** > **Authentication**.
    *   Enable **Email/Password** and **Google** providers.
    *   Add your production domain to **Authorized Domains**.
3.  **Firestore Database**:
    *   Go to **Build** > **Firestore Database**.
    *   Create database (start in **Production Mode**).
    *   Select a location (e.g., `asia-east1`).
4.  **Get Configuration**:
    *   Go to **Project Settings** > **General**.
    *   Register a Web App.
    *   Copy the `firebaseConfig` object values.

---

## 3. Vercel Deployment

1.  **Import Project**:
    *   Go to [Vercel Dashboard](https://vercel.com/).
    *   Click **Add New** > **Project**.
    *   Import your Git repository.
2.  **Configure Project**:
    *   **Framework Preset**: Next.js.
    *   **Root Directory**: `./` (default).
3.  **Environment Variables**:
    Add the following variables in Vercel Settings:
    *   `NEXT_PUBLIC_FIREBASE_API_KEY`
    *   `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`
    *   `NEXT_PUBLIC_FIREBASE_PROJECT_ID`
    *   `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`
    *   `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`
    *   `NEXT_PUBLIC_FIREBASE_APP_ID`
4.  **Deploy**: Click **Deploy**.

---

## 4. Admin Configuration

To secure the Admin Panel (`/admin`), we currently use a basic email whitelist check in the API.

1.  **Set Admin Emails**:
    *   Open `/app/api/admin/get-users/route.js` and `/app/api/admin/update-points/route.js`.
    *   Update the `ADMIN_EMAILS` array:
        ```javascript
        const ADMIN_EMAILS = ["your-admin@email.com", "another-admin@email.com"];
        ```
    *   *Note: For a more robust solution, consider moving this to Environment Variables or Firebase Custom Claims in v1.1.*

## 5. Verification & Testing

After deployment, verify the following flows:

### 🏠 Dashboard & Auth
1.  **Login**: Sign in with Google. Verify you are redirected to `/dashboard`.
2.  **Profile**: Check if your Avatar and Name appear correctly.
3.  **Level**: Verify "LV.1 Member" is shown for new users.

### 💎 Points & VIP
1.  **Daily Check-in**: Click "Daily Check-in". Verify points increase by 10.
2.  **VIP Claim**:
    *   If Level < 7: Verify button says "Locked".
    *   If Level >= 7: Verify button works and awards points.

### 👮 Admin Panel
1.  **Access**: Navigate to `/admin/users`.
2.  **List**: Verify you can see all registered users.
3.  **Modify Points**: Go to `/admin/points`. Add +100 points to a test user.
    *   Check if the Toast appears.
    *   Check if the user's dashboard updates immediately.

## 6. Health Check

To ensure the system is healthy:
1.  **API Check**: Visit `https://your-domain.com/api/health` (if implemented) or simply check if `/api/addPoints` returns 401/400 (meaning it's reachable but requires auth).
2.  **Database Connection**: If the Dashboard loads user data, Firestore is connected.

## 7. Maintenance & Updates

### Updating the App
1.  Make changes locally.
2.  Commit and push to `main` branch:
    ```bash
    git add .
    git commit -m "feat: new feature"
    git push origin main
    ```
3.  Vercel will automatically trigger a new build and deployment.

### Database Backups
*   Consider enabling **Google Cloud Firestore Backups** for automated daily backups in the Google Cloud Console.
